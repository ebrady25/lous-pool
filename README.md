# 🏌️ BirdieBuddy Pool Leaderboard

Live, auto-updating leaderboard for the golf pool. Hosted free on GitHub Pages with automated score updates via DataGolf API.

## What It Does

- **Live Scores**: Pulls tournament data from DataGolf every 15 min during rounds
- **Rule 4 Processing**: Automatically handles missed cuts, replacement players, and penalties
- **Season Tracking**: Cumulative standings across all weeks
- **Manual Refresh**: One-click live score refresh on the page itself
- **Friend Highlighting**: Highlights your team and friends on the leaderboard
- **Mobile Friendly**: Clean, responsive design

## Weekly Maintenance

Each week before the tournament starts:

### Update Rosters

Edit `data/rosters.json` to add the current week's picks for any teams you're tracking. At minimum, add your own team's picks:

```json
[
  {
    "owner": "Ethan Brady",
    "alias": "The Brady Bunch",
    "players": ["Scottie Scheffler", "Si Woo Kim", "Maverick McNealy", "Sahith Theegala"],
    "alternates": ["Cameron Young", "Sam Burns"]
  }
]
```

Player names should match DataGolf format: "First Last" (the engine handles name normalization).

### Update Season Data

After each week's commissioner results are final, update `data/season.json` with the new cumulative totals. (I can help with this each week in our chats.)

### Update Config

In `public/index.html`, update the `CONFIG.SEASON` object with the new week number, event name, and course par:

```javascript
SEASON: {
  week: 3,
  event: "Genesis Invitational",
  course_par: 71,
  season_par: 2288,  // Previous + new week's team par
},
```

## How Scoring Works

### Basic Score
Each team has 4 players. Their 4-round scores are summed. Team par = 4 players × 4 rounds × course par.

### Missed Cut (Rule 4)
When a player misses the cut:
1. **R1/R2 kept** as actual scores
2. **R3/R4 replaced** by scores from the "lowest qualifier" — players who barely made the cut
3. **Penalty added**: MC by 1 = +5, MC by 2 = +6, MC by 3 = +7, MC by 4+ = +8

Multiple missed cuts on one team get different replacement players, assigned by team listing order.

### Replacement Player Selection
Replacements are players on the cut line, sorted by R2 tee time (earliest first = finished first = first confirmed qualifier). This has been verified with 100% accuracy across 40 team assignments.

### Overuse Penalties
3 uses per player per season max. 4th use = +10, 5th = +15, 6th = +20.

## Customization

### Change Friends List
In `public/index.html`, edit the `CONFIG.FRIENDS` array:

```javascript
FRIENDS: ["Friend Name 1", "Friend Name 2", ...]
```

### Change Your Team
Edit `CONFIG.MY_TEAM` to your team owner name.

### API Key Security
The DataGolf API key is used in two places:
1. **GitHub Actions** (server-side, secured as a repository secret)
2. **Client-side refresh** (embedded in index.html for the manual refresh button)

For a friends-only pool, the client-side key exposure is fine. If you want to hide it, set up a free Cloudflare Worker as a proxy.

## Troubleshooting

- **Leaderboard is empty**: Click "Refresh Scores" to pull live data. If no tournament is active, the DataGolf API may return the last completed event.
- **GitHub Action failing**: Check the Actions tab for error logs. Most common issue is the API key secret not being set correctly.
- **Player not found**: The name matching is flexible but not perfect. Check that player names in rosters.json roughly match DataGolf's "First Last" format.
- **Wrong replacement players**: The engine uses R2 tee times from DataGolf. If the commissioner used a different method, the R3/R4 scores may differ from the official results.
